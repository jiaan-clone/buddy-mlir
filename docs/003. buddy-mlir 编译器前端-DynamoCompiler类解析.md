# buddy-mlir 编译器前端 DynamoCompiler 解析

## 前置概念
1. FX graph 是什么
FX Graph 是 PyTorch 的一种中间表示，由 `torch.fx` 提供。它把模型计算表达为一组有向节点，例如：

- `placeholder`：模型输入
- `get_attr`：权重或常量
- `call_function`：调用函数或算子
- `call_module`：调用子模块
- `output`：模型输出

ATen 是 PyTorch 底层的张量算子库。ATen Graph 通常仍然使用 FX Graph 的结构，但节点已经被规范化为底层 ATen 算子，例如：

```text
torch.ops.aten.add.Tensor
torch.ops.aten.relu.default
torch.ops.aten.mm.default
```

因此，两者的关系可以理解为：
```text
FX Graph = 图的数据结构和表达形式
ATen Graph = 使用 ATen 算子作为节点目标的 FX Graph
```

在 Buddy-MLIR 中，TorchDynamo/AOTAutograd 先生成 FX/ATen Graph，然后 `DynamoCompiler` 根据 `_ops_map` 将 ATen 算子转换成 Buddy Graph 算子：

```text
aten.mm.default → MatmulOp
aten.add.Tensor → AddOp
aten.relu.default → ReluOp
```

简而言之：FX Graph 负责“如何表示计算图”，ATen Graph 负责“用哪些规范化的 PyTorch 底层算子表示计算”。

## DynamoCompiler 简要介绍
DynamoCompiler 的核心角色是：将 PyTorch 世界中的模型和 FX/ATen Graph，转换成 Buddy-MLIR 后续编译流程能够理解的内部表示。
```text

PyTorch 前端
   │
   ▼
DynamoCompiler
   │
   ▼
Buddy Graph
   │
   ▼
MLIR Dialect / LLVM / 目标硬件
```

## GraphDriver 简要介绍
GraphDriver 的核心角色是：将一个已经分组的 Buddy Graph 拆成多个可独立编译的子图，并生成一个按正确顺序调用这些子图的主图。
“已经分组” 是指：在调用 GraphDriver 之前，Buddy Graph 中的计算节点已经被划分到一个或多个命名的算子组中。
整体关系是：
```text
PyTorch 模型
    │ DynamoCompiler
    ▼
单个 Buddy Graph
    │ 图融合/分组
    ▼
GraphDriver
    ├── subgraph0
    ├── subgraph1
    └── main graph：按依赖顺序调用各子图
```

基础 GraphDriver 主要负责把已有的算子分组变成真正的子图和主调用图；它本身不负责决定最优的分组边界。
